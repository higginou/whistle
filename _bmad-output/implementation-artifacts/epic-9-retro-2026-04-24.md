# Retrospective Epic 9 : Socle Vercel et auth admin

Date : 2026-04-24

## Resultat

Epic 9 termine. Le socle Vercel couvre maintenant le stockage Postgres, l'auth admin courte et les endpoints public/admin separes.

## Ce qui a bien marche

- Le decoupage en trois stories a force la separation schema, auth et API.
- Les revues automatiques ont trouve des risques concrets avant commit : append-only non garanti, sessions non fail-closed, API publique encore branchee sur JSON statique.
- Les tests de contrat permettent d'avancer sans base Postgres live tout en verrouillant les payloads et les erreurs API.

## Risques residuels

- Les tests SQL restent majoritairement statiques ou avec client injecte ; une passe d'integration contre une vraie base Postgres sera necessaire avant exposition production.
- Le throttling login est local a l'instance serverless ; il doit etre complete par Vercel Firewall/WAF ou un rate-limit partage avant exposition publique.
- Le choix du dernier snapshot public doit ajouter un tie-break deterministe si plusieurs snapshots partagent le meme `generated_at`.

## Actions de suite

- Epic 10 doit brancher le recalcul pour produire les snapshots Postgres consommes par l'API publique.
- Ajouter un test d'integration Postgres quand l'environnement de base de donnees sera disponible.
