# Retrospective Epic 10 : Recalcul et synchronisation

Date: 2026-04-25

Status: done

## Epic Review

Epic 10 a migré le recalcul vers le runtime Vercel : moteur pur, endpoint admin de recalcul, snapshots append-only et lecture publique via API.

### Ce qui a bien fonctionne

- Le découpage en trois stories a garde une progression nette : moteur pur, branchement serveur, puis publication front.
- Les reviews automatiques ont capture des bugs reels avant clôture : matchs scheduled traites comme nuls, historique public ecrase, calendrier incomplet, perte des bonus, double-submit final et doublons DOM apres refresh.
- Les tests de regression ont ete ajoutes au niveau utile : moteur pur, API admin, schema DB, cockpit, data fetch et rerender app.
- Les commits par story gardent une trace claire : `10-1`, `10-2`, `10-3`.

### Points difficiles

- Le contrat entre cockpit, API admin, DB et moteur de recalcul etait plus large que la premiere version de 10-2.
- Les bonus offensifs/defensifs etaient calcules cote cockpit mais pas persistés, ce qui aurait degrade le classement sans erreur visible.
- Le passage JSON statique -> API publique a expose un probleme de rerender idempotent dans l'app existante.

### Decisions conservees

- Le recalcul reste complet et deterministe : pas de delta incremental fragile.
- La publication publique passe par `projection_snapshots` append-only et `GET /api/public/season`.
- Le front public garde un fallback silencieux localStorage/null en cas d'erreur reseau.
