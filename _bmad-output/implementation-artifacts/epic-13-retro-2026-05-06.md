# Retrospective Epic 13 : Interface admin Vercel

Date : 2026-05-06
Status : done

## Epic Review

Epic 13 a transforme le runtime Vercel initialise en parcours exploitable depuis l'application : acces `/admin`, session protegee, recalcul manuel, diagnostic public et runbook de deploiement. L'administrateur peut maintenant creer ou verifier le snapshot public sans console navigateur comme procedure normale.

## Stories Livrees

- 13.1 : Acces admin protege, login via `POST /api/admin/login`, session via `GET /api/admin/session`, route `/admin` autonome.
- 13.2 : Recalcul manuel via `POST /api/admin/recompute` avec `{ seasonId: '2025-2026' }`, affichage `snapshotId` et `matchday`.
- 13.3 : Diagnostic public via `GET /api/public/season?season=2025-2026`, mapping des etats publics et relance apres recalcul.
- 13.4 : Runbook de deploiement admin, variables Vercel, initialisation DB, verification et diagnostics operationnels.

## Ce Qui A Bien Fonctionne

- Le gate maquettes de 13.1 a evite d'ecrire une nouvelle UI admin sans direction validee.
- Le scope des stories est reste progressif : acces, action de recalcul, diagnostic, documentation.
- Les reviews automatiques ont capture des bugs concrets avant cloture : route `/admin/`, erreurs non-JSON, pannes DB mappees en mauvais statut, concurrence diagnostic, payload public incomplet, documentation stale.
- Les validations completes sont restees vertes apres chaque correction majeure : Vitest, Biome, build Vite/PWA.
- Le runbook final remplace la conversation comme source operationnelle et documente les erreurs connues.

## Corrections Post-Review

- 13.1 : fixture `data/2025-2026.json` alignee, mapping login non-JSON corrige, `/admin/` normalise.
- 13.2 : `/api/admin/recompute` retourne `503 storage-unavailable` pour les pannes DB/config au lieu de masquer ces cas en recalcul impossible.
- 13.3 : les reponses de diagnostic obsoletes sont ignorees et le payload public est valide avant affichage `JSON public disponible`.
- 13.4 : le todo Vercel ne pretend plus que l'UI admin manque et le diagnostic `503 storage-unavailable` couvre aussi schema/migrations/erreurs SQL.

## Lecons Apprises

- Les erreurs operationnelles doivent etre mappees selon l'action possible par le mainteneur, pas seulement selon l'endroit ou elles apparaissent dans le code.
- Une UI admin minimale doit fonctionner sans snapshot public, sinon elle ne peut pas debloquer le premier snapshot.
- Les diagnostics publics doivent gerer la concurrence : une reponse lente pre-recalcul ne doit pas ecraser l'etat post-recalcul.
- La documentation d'exploitation doit etre revue comme du code : un texte stale peut envoyer le mainteneur vers le mauvais flux.
- Les artefacts non committes de deploiement doivent etre visibles explicitement dans les runbooks lorsqu'ils restent necessaires a l'initialisation.
